# ロードマップ

## 優先順位

| 優先 | 提案 | 理由 | 規模 | フェーズ |
| --- | --- | --- | --- | --- |
| P0 | [コードインテリジェンス層](features/01-code-intelligence.md) | 大規模リポジトリでの「読む場所探し」は全タスクに効く。既存の grep/glob を置き換えず補完できる | L | 1 |
| P1 | [チェックポイント / 一括 undo](features/04-checkpoints.md) | 既存の snapshot / revert を土台にでき、実装コストが低い割に事故耐性が大きく上がる | S–M | 1 |

| P2 | [マルチエージェント編成](features/05-multi-agent.md) | 既存の worktree / subagent を組み合わせ、並列開発の UX を作る | L | 3 |
| P3 | [小さく効く改善](features/06-quick-wins.md) | 単体で完結し、いつでも差し込める | S each | 随時 |

## フェーズ計画

### Phase 1: 理解と安全（基盤）

1. コードインテリジェンス層
   - 索引ストアと増分更新
   - `code_index` ツール（experimental）
   - `/index` ステータス表示
2. チェックポイント
   - 名前付きチェックポイントの作成・一覧・復元
   - TUI からの復元導線

### Phase 2: 検証と統制

3. テスト連動ループ
   - 変更ファイル → 関連テストの対応付け
   - 失敗ログの要約とエージェントへの差し戻し
4. 予算ガードレール
   - セッション / プロジェクト単位のトークン・コスト上限
   - ソフト警告とハード停止、TUI 表示

### Phase 3: 並列化と共有

5. マルチエージェント編成
   - プランから worktree 単位のサブタスクへ分割
   - 差分の統合レビュー UI
6. 小さく効く改善を随時
   - セッション横断検索とエクスポート
   - ツール出力の注入防御
   - タスク種別ごとのモデルルーティング

## 評価指標（案）

- タスク完了までのツール呼び出し回数と入力トークン数
- 「見当違いのファイルを読む」割合（read/grep の空振り率）
- テスト失敗の検出から修正までのステップ数
- セッションあたりのコスト分布と上限到達率
- 並列実行時のコンフリクト率とマージまでの時間
